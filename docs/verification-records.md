## 1. 自动验证基线

每次修改后执行：

`sh
pnpm verify
scripts/dry-run.sh --check
`

`pnpm verify` 当前执行：

`
build → bundle → node --check lib/client.js → node --check lib/index.js → node --test "test/*.test.ts"
`

测试数量随提交变化，文档不固定测试总数；以当前命令输出和 CI 为准。

自动化覆盖的主要领域：

- Markdown 流式过滤与 chunk 不变性；
- 出站媒体结构、AES padding、媒体类型常量；
- 入站图片/文件/视频下载与路径安全；
- QR 配对状态机与 `local_token_list`；
- `bot_agent` 清洗；
- 发送错误分类、窗口配额、MUST 消息恢复；
- 会话事件 API 漂移与重启恢复；
- Web 设置面板契约与安全边界。

## 2. Markdown 生产通道实测

**时间：2026-08-16**

单发综合 Markdown 消息，`markdownMode=passthrough`。

| 元素 | 结果 |
|---|---|
| h1–h4 | ✅ |
| 粗体 | ✅ |
| 非 CJK 斜体 | ✅ |
| CJK 斜体 | ⚠️ 客户端字体/样式异常 |
| 行内代码 | ✅ |
| 列表 | ✅ |
| 引用块 | ✅ |
| 表格 | ✅ |
| 代码块 | ✅ |
| 分隔线 | ✅ |
| 普通链接 | ✅ |

结论：默认 `passthrough` 保留最多原始 Markdown；需要更保守的兼容策略时使用 `filter`；`plain` 用于完全不依赖 Markdown 的场景。

## 4. 发送窗口验证

**时间：2026-08-19**

三次独立实测均观察到：同一用户的一次入站窗口内约 10 条成功出站，第 11 条出现 `prepare failed`；下一条用户入站消息后窗口恢复。

因此：

- `sessionWindowSendMax` 默认 10；
- 非关键进度消息在窗口耗尽后跳过；
- 最终答案、审批、错误/停止通知使用 MUST 优先级并进入恢复重推；
- 不再把该现象解释为单纯 `context_token` 过期。

> 10 条是项目实测保护值，不是腾讯公开协议常量。

## 5. 2026-09-10 宿主 API 漂移事故

DSH 0.1.5 移除 `Session.events`，改为 `snapshotEvents()`。旧代码运行时访问 `undefined`，导致第二轮处理崩溃。

当前修复：

- 所有会话事件读取统一经过 `src/session-events.ts`；
- 只依赖 `snapshotEvents()`；
- API 缺失/异常记录 `session-events-api-drift` 并退化为空日志；
- 浮动 promise 增加错误兜底；
- 重启后优先恢复 peer 自己的主会话。

该记录用于解释当前宿主版本约束，不代表旧宿主兼容。

## 6. 2026-09-20 微信提问阻塞事故

一次 `ask_user_question` 在微信侧不可见，导致 turn 阻塞 31 分 49 秒。

当前修复：

- 微信会话自己注册 question answerer，并优先于浏览器转发器认领；
- 问题按顺序发送，支持编号、多选和自由文本回答；
- 提问提示按 MUST-DELIVER 处理；
- 用户下一条消息与 watchdog tick 均可触发重推；
- `/stop` 始终穿透；
- `questionTimeoutSec` 默认 1800s；
- dispose、超时、中断均清理 pending question。
